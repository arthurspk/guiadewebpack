## :dart: O guia para alavancar a sua carreira

> Webpack é o module bundler que popularizou o front-end moderno: ele pega o seu JavaScript, CSS, imagens e fontes espalhados em dezenas de arquivos e monta um pacote otimizado para o navegador, com code splitting, tree shaking e Hot Module Replacement. Lançado em 2012 e hoje mantido por uma comunidade independente, o Webpack perdeu espaço para ferramentas mais rápidas como Vite e Rspack em projetos novos, mas continua rodando por trás do Create React App legado, de boa parte das aplicações Angular (via Angular CLI) e de milhares de projetos corporativos em produção. Este guia reúne documentação oficial, cursos, livros, ferramentas do ecossistema e um capítulo sobre usar IA na prática — para quem precisa manter, migrar ou simplesmente entender um `webpack.config.js` em 2026.

## 🗺️ Roadmap

- [webpack — Concepts (documentação oficial)](https://webpack.js.org/concepts/) — Os cinco conceitos centrais (entry, output, loaders, plugins, mode) que sustentam tudo o resto no Webpack.
- [Awesome webpack (lista oficial)](https://webpack.js.org/awesome-webpack/) — Curadoria oficial de recursos, ferramentas e integrações, organizada pelo próprio time do projeto.
- [Learn Webpack (Hackr.io)](https://hackr.io/tutorials/learn-webpack) — Agregador que ranqueia cursos e tutoriais de Webpack recomendados pela comunidade.
- [Migrando para o Webpack 5 (guia oficial)](https://webpack.js.org/migrate/5/) — Passo a passo oficial para quem ainda mantém projetos em versões antigas.

**Trilha resumida:** entenda os cinco conceitos centrais → suba um `webpack.config.js` mínimo com `webpack-dev-server` → aprenda loaders (Babel, CSS) e plugins (`HtmlWebpackPlugin`) → configure ambientes separados de desenvolvimento e produção → estude code splitting e tree shaking → avance para Module Federation se for trabalhar com micro-frontends → conheça as alternativas modernas (Vite, Rspack, Turbopack) para saber quando migrar.

## 🛠️ Ferramentas

> Loaders e plugins essenciais

- [html-webpack-plugin](https://github.com/jantimon/html-webpack-plugin) — Gera automaticamente o HTML final referenciando os bundles gerados.
- [css-loader](https://github.com/webpack/css-loader) — Interpreta `@import` e `url()` dentro de arquivos CSS.
- [style-loader](https://github.com/webpack/style-loader) — Injeta CSS no DOM via tags `<style>`.
- [mini-css-extract-plugin](https://github.com/webpack/mini-css-extract-plugin) — Extrai o CSS para arquivos separados em vez de embutir no JavaScript.
- [babel-loader](https://github.com/babel/babel-loader) — Transpila JavaScript moderno com Babel dentro do pipeline do Webpack.
- [ts-loader](https://github.com/TypeStrong/ts-loader) — Integração do compilador TypeScript com o Webpack.
- [fork-ts-checker-webpack-plugin](https://github.com/TypeStrong/fork-ts-checker-webpack-plugin) — Roda a checagem de tipos do TypeScript em paralelo, sem travar o build.
- [terser-webpack-plugin](https://github.com/webpack/terser-webpack-plugin) — Minificador de JavaScript usado por padrão no modo de produção.
- [copy-webpack-plugin](https://github.com/webpack/copy-webpack-plugin) — Copia arquivos e diretórios estáticos para a pasta de build.
- [clean-webpack-plugin](https://github.com/johnagan/clean-webpack-plugin) — Limpa a pasta de output antes de cada novo build.
- [eslint-webpack-plugin](https://github.com/webpack/eslint-webpack-plugin) — Roda o ESLint como parte do processo de build.

> Análise, performance e configuração

- [webpack-bundle-analyzer](https://github.com/webpack/webpack-bundle-analyzer) — Gera um mapa visual interativo do que está ocupando espaço no bundle final.
- [speed-measure-webpack-plugin](https://github.com/stephencookdev/speed-measure-webpack-plugin) — Mede o tempo gasto por cada loader e plugin durante o build.
- [webpack-merge](https://github.com/survivejs/webpack-merge) — Combina configurações de desenvolvimento e produção sem duplicar código.
- [esbuild-loader](https://github.com/privatenumber/esbuild-loader) — Troca Babel/Terser pelo esbuild dentro do Webpack para builds até 10x mais rápidos.
- [swc-loader](https://swc.rs/docs/usage/swc-loader) — Alternativa em Rust ao Babel, usável como loader dentro do Webpack.
- [Workbox (webpack plugin)](https://developer.chrome.com/docs/workbox) — Gera service workers para cache offline e PWAs a partir do build do Webpack.

> Alternativas e integrações modernas

- [Rspack](https://rspack.rs/) — Bundler em Rust com API compatível com o Webpack, criado para acelerar builds sem reescrever a configuração existente.
- [web-infra-dev/rspack (repositório oficial)](https://github.com/web-infra-dev/rspack) — Código-fonte do Rspack, mantido pela ByteDance e pela comunidade.

## 🤖 IA na prática

O Webpack tem 12 anos de opções de configuração acumuladas — exatamente o tipo de complexidade em que um assistente de IA ajuda muito, desde que você confira o resultado no compilador e no bundle final, não só no "parece que funcionou".

**Para aprender**
- Cole o seu `webpack.config.js` inteiro e peça para a IA explicar, bloco por bloco, o que cada `entry`, `output`, `rule` e `plugin` está fazendo — é a forma mais rápida de entender uma configuração legada que você não escreveu.
- Peça exemplos comentados de configurações comuns: "webpack.config.js mínimo para um projeto React com TypeScript e CSS Modules" ou "configuração de produção com code splitting e content hashing".
- Cole uma mensagem de erro do Webpack (ex.: `Module not found: Error: Can't resolve...`) e peça a causa mais provável e como corrigir — o erro sozinho raramente diz onde está o problema real.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para: escrever loaders e plugins customizados, migrar `webpack.config.js` de CommonJS para ESM, adicionar Module Federation a um projeto existente ou traduzir uma configuração do Webpack para o formato equivalente do Vite ou do Rspack durante uma migração.
- Peça para a IA gerar um `webpack-bundle-analyzer` de comparação "antes e depois" de uma otimização e explicar, com base no relatório, quais dependências valem a pena trocar ou remover.
- Depois de qualquer sugestão de configuração aceita, rode o build (`webpack --mode production`) e confira o bundle gerado com o [webpack-bundle-analyzer](https://github.com/webpack/webpack-bundle-analyzer) antes de considerar a tarefa concluída.

**Limites e boas práticas**
- IA erra o **nome de opções antigas ou removidas** (o Webpack mudou bastante entre as versões 3, 4 e 5) — confira sempre na [documentação oficial de configuração](https://webpack.js.org/configuration/) antes de aplicar.
- Ela tende a sugerir plugins abandonados ou incompatíveis com Webpack 5 (que exige polyfills explícitos de Node.js no navegador). Verifique a última atualização do pacote no npm antes de instalar.
- Para projetos onde o Webpack não é mais necessário, a IA é uma ótima ferramenta para **avaliar objetivamente** se vale migrar para Vite/Rspack — peça uma análise de custo-benefício específica do seu projeto em vez de seguir hype.
- Não cole segredos, tokens de API ou configurações de infraestrutura da empresa em ferramentas de IA sem verificar a política do seu empregador.

## 🎓 Certificações

Não existe certificação oficial de Webpack — o projeto é mantido por uma comunidade independente, sem uma entidade emissora de certificados. Empregadores avaliam **projetos publicados e domínio prático** (saber ler e ajustar um `webpack.config.js` real). O certificado abaixo é de conclusão de curso: ajuda no currículo, mas não substitui portfólio.
